# Phase 10 and 11 independent gate review — 2026-10-04

**Decision: Phase 10 installed-wheel verification is unstable; Phase 11 requires
changes. All gates are not met.**

Reviewed specification v0.9.6, the current working tree, historical gate evidence,
artifact manifests, installed package contents, and additional adversarial
contract cases. Scope is local Windows AMD64 with the project Python runtime,
native KiCad, wxPython, Tesseract and the released OpenAI adapter. Remote CI and
other operating systems were not verified. Production code was not changed by
this review. The earlier Phase 11 PASS report does not cover the new failing cases.

## Findings

1. **P2 — Missing order numbers can become inferred package candidates.**
   `src/partsmith/ai/contracts.py:329` checks that the returned part number equals
   the requested part number, but does not check that it appears in the cited
   ordering information. An exact quotation from an unrelated order entry is
   sufficient. The independent probe requests `ABSENT-TSSOP-28R` from Evidence
   containing only `TEST-QFN-16R / QFN-16`; a provider payload claiming
   `ABSENT-TSSOP-28R / TSSOP-28` is accepted as `INFERRED` with no ambiguity or
   conflict. This contradicts the Phase 11 report's missing-order guarantee and
   leaves a required ambiguity unsurfaced. Human review still blocks production;
   this finding does not demonstrate an approval bypass. Require source grounding
   for the full order number and retain an unresolved issue when grounding is absent.

2. **P2 — Provider revalidation changes valid exact-decimal request bindings.**
   `src/partsmith/ai/contracts.py:210` decodes an immutable canonical snapshot
   through ordinary `json.loads`, rounding decimal numbers to binary floats.
   `src/partsmith/ai/openai.py:220` recreates the request from that rounded data.
   A schema-valid source Evidence value `Decimal('0.9876543210987654321')` becomes
   `0.9876543210987654`, changing the input hash. The returned result no longer
   matches the caller's request; `candidate_evidence` rejects it at
   `src/partsmith/ai/workflow.py:18`, and offline replay cannot use the original
   request binding. Preserve exact numeric tokens through validation and
   serialization, and test that the original request hash survives the provider
   and Evidence workflow unchanged. Inner `value_json` precision tests alone do
   not cover this request-path defect.

Both findings reproduce offline with a dummy credential and deterministic fake
transport. No provider variability or external service failure is involved.

3. **P2 — The installed-wheel corpus run terminated in the native PDF parser.**
   The combined installed-wheel run ended with a Windows access violation in
   PyMuPDF `table.row_has_bold` / `page_get_textpage`, called by
   `src/partsmith/extraction/document.py:320`. No complete JUnit result was
   produced. All 638 source/native regression cases had passed immediately
   before this attempt, and all 75 package files matched the installed wheel's
   content. No installation or production edit overlapped either run. Similar
   access violations are already recorded in the Phase 10 manifest. This is
   parser instability, not evidence of a new deterministic extraction defect.
   GUI/CLI process isolation contains a crash but returns an extraction error;
   it does not guarantee corpus extraction succeeds. Preserve this failed attempt
   when assessing the subsequent isolated extraction rerun. Stabilize the parser
   path or establish and record a supported, reliable runtime before claiming
   unconditional installed-wheel acceptance.
