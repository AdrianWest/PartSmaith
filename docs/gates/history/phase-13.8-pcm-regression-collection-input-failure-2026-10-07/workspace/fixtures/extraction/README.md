# Synthetic multilingual extraction fixtures

`language-matrix.pdf` contains eight pages: English native/scanned (1/2),
German native/scanned (3/4), Simplified Chinese native/scanned (5/6), and mixed
English/German/Chinese native/scanned (7/8). Scanned pages contain only an image
of their native counterpart, with no hidden text layer. These are test samples,
not manufacturer-backed engineering evidence.

`language-matrix.json` retains the PDF hash, language/page mapping, and explicit
manual fixture translations with original text and provenance. Reference OCR
uses 300 DPI and Tesseract text-block segmentation mode 6. Tests require known
language tokens and numerals, retain word confidence, and leave engineering
interpretation UNKNOWN. OCR is not asserted to be error-free.

The mixed sample uses `chi_sim+eng+deu`, with its dominant Chinese text as the
primary OCR language. Tesseract's recognition depends on language order; using
English first misses the Chinese title on Ubuntu's Tesseract 5.3.4. The test
requires the Chinese title, English package label, full test order number, and
numerals rather than assuming every engine produces identical text. See
[Tesseract's language-order documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html#order-of-multiple-languages).

Rebuild the PDF with `python scripts/generate_extraction_fixtures.py`. If its
bytes change, review and update the JSON source hash and retained translations.
The generator uses PyMuPDF's built-in Latin and Chinese fonts and lossless
compression. The coordinate tests generate separate small fixtures for all
four rotations, two DPI settings, shifted MediaBox/CropBox, and UserUnit 1/2.
Ordering-table, ambiguous-package, encrypted, and scanned-grid cases are also
generated by the tests. Original real-part PDFs remain in `test_data_sheets/`.
